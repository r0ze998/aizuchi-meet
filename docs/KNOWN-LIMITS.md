# 既知の制約

- **呼び出しの手間**: tabCapture は「ユーザーが拡張を呼び出したタブ」にしか使えません。Meet タブでアイコン（または ⌘⇧Y）を押してから「開始」が必要です。別オリジンへ移動すると許可が失効します（Meet の待機室→会議室は同一オリジンなので持続する想定ですが、実通話では未検証）。
- **ブランド版 Chrome の自動テスト**: Chrome 137 以降は `--load-extension` を無視するため、自動検証は Chrome for Testing 155 で行いました。手動の「パッケージ化されていない拡張機能を読み込む」は通常の Chrome で使えます。
- **実経路の自動化**: アクションクリック／ショートカットは CDP でも osascript（キー操作が許可されていない）でも再現できず、未検証です。ゲートが働くこと（呼び出し前は拒否）は確認済みです。
- **Web Speech API**: 既定（サーバーモード）は音声を Google に送ります。連続認識は一定時間で終了して再開するため、再開に 600 ms 以上かかった区間は「取りこぼしの可能性」として表示します。話者の識別はできず、重なった発話は 1 本の文字起こしになります。`start(MediaStreamTrack)` は MDN 上「実験的」ですが Chrome 155 で動作しました。
- **翻訳品質**: 端末内の Translator API は機械翻訳相当です。専門用語の訳が崩れることがあります。
- **候補の品質と遅延**: モック中継では規則ベースの候補です。本物のモデルの遅延は未計測で、Opus 5.5 は思考を伴うため 1〜2 秒の目標に届かない可能性があります（Haiku 5.5 への切り替えで対応）。
- **Gemini Nano（Prompt API）**: 実装のみ。モデル（数 GB）のダウンロードを伴うため未検証です。
- **自分のマイク**: 実装のみ。許可 UI を伴うため自動テストでは未検証です。
- **サイドパネルのスクリーンショット**: ハーネスは同じページをタブとして開いて撮影しています（見た目は同じですが、本物のサイドパネルではありません）。
- **停止後の表示**: 既定では停止時にメモリから破棄しますが、パネルに最後の表示は残ります（次の開始で消えます）。
- **一時停止**: 認識と候補生成を止めますが、会議音声の再生経路は維持します（聞こえなくならないため）。
- **複数の Meet タブ**: 同時に取得できるのは 1 タブだけです。
