# 遅延の計測

更新: 2026-10-24。計測はすべて **専用 Chrome（Chrome for Testing 155）＋テスト用合成音声（macOS `say`）** での値です。返答候補は **偽 Anthropic API（直接接続）** と **モック中継** の 2 方式で計測しました。**実際の Meet 通話と実際の Claude API の遅延は含みません。** これは検証目標の確認であって、達成の保証ではありません。

## 計測方法

`extension/lib/pipeline.js` が各区間を記録し、サイドパネル下部に p50 / p95 を表示します（「JSON をコピー」で書き出し）。ハーネス `test/harness/e2e-speech.mjs` は、再生ページ側の再生開始・終了時刻を基準にした実測（下表「再生基準」）も別に取ります。p50 / p95 は最近傍順位法。音声は 16 kHz モノラルの合成音声 12 本（`test/fixtures/audio/`）。

## 認識と翻訳（中継モードのフルラン、2026-10-24）

| 区間 | n | p50 | p95 | 備考 |
|---|---|---|---|---|
| 音声取得→認識（発話開始→最初の途中結果） | 12 | **488 ms** | 779 ms | Web Speech（Google サーバーモード） |
| 音声取得→認識（発話終了→確定） | 10 | **769 ms** | 873 ms | 最後に音が出てから確定テキストまで |
| 認識→翻訳（途中訳） | 30 | 471 ms | 473 ms | **モック翻訳**（下記注） |
| 認識→翻訳（確定訳） | 9 | 120 ms | 126 ms | **モック翻訳** |
| 再生開始→最初の途中結果（再生基準） | 11 | 647 ms | 4749 ms | p95 は最初に 4 秒の無音があるシナリオ（q12） |
| 再生終了→最後の確定（再生基準） | 10 | 570 ms | 702 ms | |

## 返答候補

| 区間 | 直接接続（偽 API） | モック中継 |
|---|---|---|
| 質問の確定→最初の候補 | **p50 539 ms / p95 553 ms**（n 9） | p50 356 ms / p95 364 ms（n 9） |
| 質問（暫定）→最初の候補 | p50 545 ms / p95 564 ms（n 14） | p50 355 ms / p95 375 ms（n 18） |
| 候補生成の完了まで | p50 653 ms / p95 673 ms（n 23） | p50 509 ms / p95 662 ms（n 27） |
| 言い直し→結果 | 527 ms（n 1） | 353 ms（n 1） |

偽 API は最初の文字を **400 ms** 後に返すよう設定しています。したがって直接接続で拡張側が上乗せする時間（公式 SDK の通信・ストリーム解析・パイプライン・画面更新）は **約 140〜150 ms** です。実際の待ち時間は、ほぼ Claude が最初の文字を返すまでの時間で決まります。モック中継は設定 350 ms の遅延です。

## 目標との比較（検証目標。保証ではない）

- 目標「日本語訳が数秒程度の遅れで追従」: 認識の途中結果が p50 約 0.5 秒、翻訳はモックで +0.1〜0.5 秒。**端末内翻訳（Translator API）の実時間は未計測**（下記注）。
- 目標「質問が安定してから最初の短い候補が 1〜2 秒程度」: 拡張側の上乗せは約 0.15 秒。**実 Claude の応答開始までの時間は未計測**です。Opus 5.5 は思考を伴うため 1〜2 秒に収まらない可能性があり、その場合は設定でモデルを Haiku 5.5 にすると速くなります。

## 重要な注記（何が「本物」で何が「偽／モック」か）

- **音声認識**: 本物（Chrome Web Speech API、Google サーバーモード）。端末内認識の言語パックはこの環境では「ダウンロード中」のままでした。
- **翻訳**: Translator API の en→ja モデルが自動テストの専用プロファイルではダウンロード完了しなかったため、E2E はモック翻訳です。実時間は未計測。
- **候補生成**: 偽 Anthropic API（`test/harness/fake-anthropic.mjs`、本物と同じ SSE 形式・公式 SDK で受信）とモック中継。実 Claude の遅延・費用・日本語の質は未計測。
- 古い生成の中止（`AbortController`）、短い待機、翻訳キューの上限、取りこぼし表示は実装・テスト済み。認識テキスト 1 文字ごとに候補 API を呼ぶことはしません（質問の確定・暫定のタイミングでのみ生成）。
