## 1. tabCapture（モックで確認 / 一部 実環境で確認）

対象: Chrome for Testing 155、テスト用トーン／別タブトーンのページ。ブランド版 Chrome は `--load-extension` を無視するため専用 Chrome を使用。結果の生データ: `test/out/capture-verify.json`。

| 要求項目 | 結果 | 根拠 |
|---|---|---|
| Meet（対象）タブの音声を取得できる | **PASS** | 対象タブの 440 Hz トーンを offscreen の AudioContext で検出（dominantHz≈431、録音・外部送信なしで周波数解析） |
| 元の会議音声を聞き続けられる | **PASS（経路）** | 取得ストリーム→`AudioContext.destination` 接続を確認。タブ側の再生も継続。**スピーカーからの聴感は自動計測不可 → 実通話で要確認** |
| 別タブの音声が混ざらない | **PASS** | 別タブで 880 Hz を鳴らしても取得側は 440 Hz のまま（880 Hz のピークは検出されず） |
| 取得音声は対象タブに追従 | **PASS** | 対象タブを 440→523 Hz に変えると取得側も追従 |
| 任意マイクを有効にしなければ自分のマイクを取得しない | **PASS** | `micActive=false`、トラックラベルにマイク無し、mic 未有効 |
| 停止すると取得が止まる | **PASS** | トラック `ended`、AudioContext `closed`、capture 状態 `stopped`、タブ側再生は継続、文脈はメモリから破棄 |
| 一時停止中も会議音声の再生経路は維持 | **PASS** | 一時停止中も passthrough と AudioContext が running |
| 開始／停止を繰り返せる | **PASS** | 3 回連続で開始→取得→停止 |
| 対象タブを閉じると取得が止まる | **PASS** | タブ終了で自動停止（理由 track-ended） |
| 呼び出し前は取得が拒否される（activeTab 型のゲート） | **PASS** | 呼び出し前の `getMediaStreamId` が `needs-invoke` で拒否 |
| 実経路: ショートカット（⌘⇧Y）で拡張を呼び出すと取得できる | **PASS（実キー入力）** | osascript で実際に ⌘⇧Y を送出 → `action.onClicked` 発火 → 対象タブを取得（dominantHz≈431）。この拡張 ID は allowlist なしの通常プロファイル |

メモ（NOTE）: 実サイドパネルが CDP のデバッグ対象として現れないため、サイドパネルの「開く」自体は自動検証では未確認（取得は成功）。スクリーンショットはハーネスが同一ページをタブとして開いて撮影。

## 2. 認識→翻訳→候補の一連の流れ（モックで確認）

対象: 合成英語音声 12 本（通常の質問、途中の言い直し・否定、早口、長文、無音、重なり、固有名詞・金額・日付、登録情報外、矛盾、説明文）。中継はモック（費用ゼロ）。結果: `test/out/e2e-speech.json`。

| 要求項目 | 結果 | 根拠 |
|---|---|---|
| 通常の質問 → 要約＋最大 3 候補、訳つき転記 | **PASS** | 各質問で日本語要約と候補（≤3、互いに別方針）を生成 |
| 途中の言い直し・否定に対応 | **PASS** | q02「forget that」・q08「no wait, not this year」で訂正を検知し、進行中の生成を中止して作り直し。暫定候補は「暫定」表示 |
| 費用・契約の質問で勝手に承諾しない | **PASS** | q06（固定価格＋契約）で候補が「保留する／条件を尋ねる／確認する」のみ、全件「要確認・約束しない」フラグ。承諾文は生成されない |
| 登録情報にない質問 | **PASS** | q07 で登録情報を根拠にせず、聞き返し・保留の候補 |
| 説明文を質問扱いしない | **PASS** | q10 は「質問ではなく説明」と要約し、相づち・聞き返しの反応候補 |
| 固定した候補は更新で消えない | **PASS** | 候補を固定後、新しい質問が来ても固定欄の英文は不変（別 ID で保持） |
| 「これを話した」は押したものだけ履歴に反映 | **PASS** | 表示しただけの候補は文脈に入らず、押した候補のみ自分の発言として追加 |
| 「こう言いたい」で英語の言い直し | **PASS** | 日本語入力から英語候補を生成 |
| 登録情報の矛盾は断定しない | **PASS** | サンプルのローンチ日が「未定」と「2026年12月」で矛盾 → q01 の候補はどちらも言わず「確認して折り返す」。ユニットテストでも確認 |
| 中継切断・API エラー・費用上限・レート上限 | **PASS** | q07 で中継を停止 → 「接続できません」を表示し黙って進まない（候補セットは error）。費用・レート上限はユニットテスト `relay.test.mjs` で 402 / 429 を確認 |
| 取りこぼしの表示 | **PASS** | 認識器が発話途中で終了した場合、未確定テキストを「未確定」表示で残し、取りこぼしの可能性を通知 |

認識精度（WER、Google サーバーモード、合成音声）: 平均 0.19（10-17 の実行）と 0.36（10-24 の実行）で、同じ音声でも実行ごとに揺れます。多くは 0（完全一致）ですが、早口の短文（q04）や否定を含む長めの文（q08）が空や途中までになる回があり、固有名詞・金額は `$20,000`・`15,000`・`March 3rd` のように表記化されて誤差が出ます。**認識は非決定的で、実通話では声・マイク・回線で変わります。** 誤認識はパネルに原文が出るので、あなたが気づけるようにしています。

## 3. 拡張から Anthropic への直接接続（モックで確認）

本物の API は呼ばず、本物と同じ SSE 形式で応答する偽 API（`test/harness/fake-anthropic.mjs`）に、同梱の公式 SDK（`@anthropic-ai/sdk` 0.135.0 のブラウザ用ビルド）で接続して確認しました。結果: `test/out/e2e-speech-direct.json`、`test/unit/direct.test.mjs`。

| 要求項目 | 結果 | 根拠 |
|---|---|---|
| 中継なしで、拡張から直接ストリーミング接続 | **PASS** | 実際の Chrome で 37 回のリクエストすべてが公式 SDK 経由（ブラウザ用ヘッダー、ストリーミング、プロンプトキャッシュ、Opus での拒否時フォールバック、effort low） |
| 設定画面の「接続を確認」は無料 | **PASS** | トークンを使わないモデル API（`models.retrieve`）で確認。成功時は「接続OK」 |
| API キーを表示・状態・ログに出さない | **PASS** | 設定画面は末尾 4 文字のみ、入力欄は保存後に空。取得処理の状態とパネル表示にキー本体なし |
| キー未設定・無効なキー | **PASS** | 未設定は送信せず案内、無効キー（401）は「API キーが無効です」 |
| 混雑（529）・回数上限・費用上限 | **PASS** | 529 は 1 回再試行後に「Anthropic が混雑しています」。費用上限・回数上限は次のリクエストを送る前に止める |
| キャンセル時の費用 | **PASS** | 新しい発話で中止した生成は控えめな推定額を加算 |
| 費用の表示 | **PASS** | パネルに「この会議の推定費用 $…（上限 $…）」 |

## 4. 中継のセキュリティ（実装済み・ユニットで確認）

`test/unit/relay.test.mjs`:

- ループバック（127.0.0.1）専用。許可した拡張 ID 以外の `Origin` は 403、別オリジン（例: localhost:ポート）も 403。
- ペアリングトークン不一致は 401。プリフライトは 204。
- `/v1/health` は秘密を一切返さない。SSE で候補をストリーム。
- セッション費用上限（402）、毎分リクエスト上限（429）、過大ボディ（413）を確認。
- API キーは中継プロセスの環境のみ。本文・キーはログに出さない（`RELAY_LOG_BODIES=1` で明示有効化しない限り）。
